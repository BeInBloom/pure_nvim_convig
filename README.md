## Elixir и Clojure

Mason устанавливает `elixirls` и `clojure_lsp` при запуске Neovim.

Для Elixir нужен установленный Elixir/Erlang (включая приложения `public_key` и `ssl`) и проект с `mix.exs`. ElixirLS запускает Dialyzer, показывает ошибки типов и предлагает `@spec`. На Arch Linux с модульным Erlang установите пакеты `erlang-public_key` и `erlang-ssl` (зависимости загрузятся автоматически).

Для Clojure нужен Java. В проекте с `deps.edn`, `project.clj` или другим маркером clojure-lsp предоставляет полные возможности; одиночный файл тоже получает диагностику clj-kondo, но часть возможностей сервера ограничена без корня проекта. Clojure не имеет встроенной статической типизации; если требуется именно проверка аннотаций типов, её нужно подключать отдельно в проекте.

## Rust

`rust-analyzer` запускает rustaceanvim (`lua/plugins/rust.lua`), а не nvim-lspconfig. Сервер берётся из rustup, чтобы его версия совпадала с тулчейном:

```sh
rustup component add rust-analyzer
```

Не устанавливайте `rust-analyzer` через Mason: он окажется первым в `PATH` и заменит версию из rustup.

## Одиночные файлы

Для файлов вне проекта подключаются поддерживающие их LSP: `gopls`, `ruff` и `pyrefly`, `lua_ls`, `zls`, `clojure_lsp`, `html`, `cssls`, `ts_ls` и `svelte`. Для JS/TS и Svelte корнем без маркеров становится каталог файла, а не текущий рабочий каталог Neovim. `pyrefly` использует preset `default` для файлов без собственной конфигурации, чтобы показывать ошибки типов; настройки `pyrefly.toml` в проектах продолжают действовать. `golangci-lint` проверяет сам файл, если рядом нет `go.mod`, независимо от того, из какого каталога запущен Neovim.

ESLint без собственного конфига и Tailwind без проекта не запускаются. Для полноценной работы ElixirLS нужен проект с `mix.exs`. `rust-analyzer` подключается и к одиночным `.rs` файлам, но диагностики cargo и clippy есть только в Cargo-проекте.

Текущий файл обновляется после внешней записи по событию файловой системы, включая атомарную замену файла. Несохранённые изменения в буфере не перезаписываются. При возвращении в окно или в Neovim также выполняется `:checktime`.

## Форматирование Svelte через Prettier

`prettier-plugin-svelte` установлен один раз в Prettier от Mason, а не в каждый проект:

```sh
cd ~/.local/share/nvim/mason/packages/prettier
npm install prettier-plugin-svelte --no-save
```

`lua/plugins/formatting.lua` передаёт Prettier абсолютный путь до `plugin.js`, поэтому плагин работает из любого проекта. Если Mason обновит или переустановит Prettier, плагин пропадёт: повторите команду выше. Пока плагин отсутствует, конфиг просто не передаёт аргумент `--plugin`, и Svelte не форматируется (без ошибок в остальных типах файлов).
